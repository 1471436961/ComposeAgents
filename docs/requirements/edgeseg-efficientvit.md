# EdgeSeg-EfficientViT 项目需求

## 1. 我想完成什么

我希望基于 MIT Han Lab 的 EfficientViT，完成一个面向机器人感知与边缘部署的语义分割推理优化项目。
目标模型优先采用 EfficientViT-Seg-B0，使用 Cityscapes 预训练权重，在我的本地电脑上完成实际实验。

这个项目用于展示 AI 推理优化工程师 / 机器人感知算法工程师所需的能力。
核心是深入模型计算与实际运行过程，开发有证据支撑的 C++/CUDA TensorRT 自定义算子，
并将其集成到真实模型中验证。除了速度，还要保证模型语义、实验可信度和工程可复现性。

## 2. 我能提供的资源

- 官方源码起点：[MIT Han Lab EfficientViT](https://github.com/mit-han-lab/efficientvit)。
- 本地 Windows 电脑，GPU 为 NVIDIA GeForce MX250，2GB 显存，Pascal 架构，计算能力 6.1。
- CPU 为第十代 Intel Core i5，内存 12GB。
- 已有 Windows 环境：Python 3.10.20、PyTorch 2.4.1+cu124、CUDA Toolkit 12.4、驱动 560.81、TensorRT 8.6.1。
- 已有 MSVC、CMake、Nsight Systems，可编译 CUDA 程序并采集 GPU 轨迹。

- 可提供官方预训练权重、固定输入样图和 Cityscapes 验证集，具体获准使用的路径随工作区提供。

请在独立工作区开展开发，记录实际使用的源码版本、权重、数据及软件环境。
可以查阅公开论文、官方文档和通用示例，引用的代码与材料需要注明来源；不要复用其他同题项目的专用实现、优化结论或实验结果。

## 3. 我希望得到的核心能力

### 可复现的基线与性能分析

跑通原生 PyTorch 推理，明确输入、预处理、输出以及精度口径。
以 batch size=1 为主要场景，记录延迟、吞吐量和显存占用，并用 Nsight Systems 分析实际瓶颈。

我希望重点考虑以下优化方向：

- 多尺度线性注意力模块中的 `MatMul + Softmax + Scale` 算子序列。
- `LayerNorm + 残差连接` 等可能存在融合机会的组合。
- 性能分析中发现的其他高耗时或 TensorRT 难以自动高效处理的算子路径。

需要结合源码和实际运行结果提出优化方案，解释目标为什么值得做、可能收益来自哪里。
技术判断应有证据；如果原有设想与实际情况不符，应说明依据、影响及调整后的方案。

### TensorRT 部署与对照

完成 ONNX 导出、TensorRT 引擎构建和实际推理，对照 PyTorch 检查输出。
评估 FP32 与 FP16 的可用性、精度和性能，根据本机结果选择合适的基线。
导出与构建的输入形状等配置由团队提出并说明理由，不以增加动态能力为目标。

需要有可编译、可运行的 C++ 推理入口，为最终自定义算子的集成与使用提供工程验证。

### 自定义算子与模型集成

选择一个有充分依据的优化目标，用 C++/CUDA 实现 TensorRT Plugin，完成真实模型中的替换与集成。
既要验证算子本身，也要验证集成后的模型，说明输入输出、数值处理、内存使用及兼容范围。

最终主线应在正确性和语义精度可接受的前提下，相对 TensorRT 基线取得可复测的端到端性能收益。
不能仅凭引擎构建成功、单个 kernel 变快或 launch 数变少就宣布优化完成。
如果没有实现收益，应如实报告目标未达成、已获得的证据及剩余问题。

## 4. 我如何判断成果是否可信

- 原生推理、TensorRT 基线、自定义算子和最终引擎都必须实际运行，不能用模拟结果代替。
- 需要明确 PyTorch、TensorRT 基线和 Plugin 引擎之间的比较对象，建立数值检查，并在 Cityscapes 验证集上检查最终模型的语义精度。
- 验收前明确数值容差、精度可接受范围和性能测量口径，不在看到结果后放宽标准。
- 不同方案应使用同一设备、输入与测量范围进行比较；安排预热和重复测量，注意本机温度、频率及其他 GPU 负载的影响。
- 单层收益与端到端收益分别说明，分析结论能够追溯到实际代码、命令、数据和性能轨迹。
- 不为了加速而更换任务、降低输入要求、破坏模型语义或减少评估数据却不说明。
- 失败、超时、未执行和证据不足应如实标注，不能写成通过；必要的负向实验应保留结论依据。
